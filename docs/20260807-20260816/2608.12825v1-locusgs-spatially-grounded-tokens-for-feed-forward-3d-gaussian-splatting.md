## 摘要
近期基于查询的前馈三维高斯溅射（3DGS）方法使用可学习的查询表示场景，每个查询聚合多视角证据并解码一组高斯体。理想情况下，不同的查询应专注于场景中连贯的局部区域。然而，我们观察到从同一查询解码出的高斯体常常散布在遥远的场景区域，导致查询级空间连贯性较弱，且与场景结构的对齐不佳。我们将此行为归因于现有高斯查询的纯潜在表示。为解决这一局限，我们引入了LocusGS，它为每个高斯查询增加了一个由中心和支持半径组成的三维锚定状态。该锚定状态在解码器层间逐步细化，并贯穿于查询交互、多视角特征聚合和高斯生成过程。具体而言，锚点到射线的几何偏置引导每个查询关注空间相关的图像观测，而以锚点为中心的解码则将其高斯体组织在局部区域内。在新视角合成基准上的实验表明，在相同高斯预算下，LocusGS相比基于查询的高斯标记基线提高了渲染质量。进一步分析显示，学习到的锚点形成了连贯的空间布局，并带来了更有结构的高斯分布，证明了显式锚定状态改善了空间组织。我们的项目页面：https://leo-frank.github.io/LocusGS_viewer。

## Abstract
Recent query-based feed-forward 3DGS methods represent a scene using learnable queries, each aggregating multi-view evidence and decoding a group of Gaussians. Ideally, different queries should specialize in coherent local regions of the scene. However, we observe that Gaussians decoded from the same query often scatter across distant scene regions, resulting in weak query-level spatial coherence and poor alignment with the scene structure. We attribute this behavior to the purely latent representation of existing Gaussian queries. To address this limitation, we introduce LocusGS, which augments each Gaussian query with a 3D anchor state consisting of a center and a support radius. The anchor state is progressively refined across decoder layers and is used throughout query interaction, multi-view feature aggregation, and Gaussian generation. Specifically, an anchor-to-ray geometric bias guides each query toward spatially relevant image observations, while anchor-centered decoding organizes its Gaussians within a local region. Experiments on novel view synthesis benchmarks show that LocusGS improves rendering quality over query-based Gaussian token baselines under the same Gaussian budget. Further analysis shows that the learned anchors form coherent spatial layouts and lead to more structured Gaussian distributions, demonstrating that explicit anchor states improve the spatial organization. ### 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：前馈式三维高斯溅射（Feed-forward 3DGS）旨在直接从稀疏多视角图像中预测三维场景表示，避免逐场景优化。其中，查询式（query-based）方法使用一组可学习的高斯查询（Gaussian queries），通过 Transformer 解码器聚合多视图图像证据，并解码出一组高斯原语，输出预算与图像分辨率和视角数量解耦。

- **核心问题**：现有查询式方法中，每个查询（token）完全由潜在特征（latent feature）表示，缺乏显式的空间状态。理想情况下，同一查询解码出的高斯应聚集在场景中的某个连贯局部区域，形成空间专业化分工；但实际中，同一查询解码的高斯经常散射到相距较远的区域，导致 token 级空间连贯性弱、分布弥散，并与真实场景结构对齐不良。

- **核心洞察**：造成该问题的根源在于“纯潜在查询表示”没有明确指定查询在三维空间中的作用位置和覆盖范围。作者因此提出显式三维锚点状态，将查询从隐式的潜在嵌入转变为具有空间意义的“空间锚定重建查询”，以提升前馈 3DGS 的场景结构和重建质量。

### 2. 论文提出的方法论：核心思想、关键技术细节与算法流程

#### 2.1 核心思想

- 为每个高斯查询附加一个显式的三维锚点状态（anchor state），包括：
  - **锚点中心**（μ，3D 位置）：指明查询当前在场景中的参考位置；
  - **支撑半径**（r，标量）：定义查询局部支持区域的大小。
- 锚点状态在解码器各层中逐步细化（progressively refined），并贯穿三个关键环节：
  - 查询交互（自注意力）；
  - 多视图特征聚合（交叉注意力）；
  - 高斯原语生成（解码中心预测）。

#### 2.2 关键技术细节

1. **锚点状态参数化**：
   - 原始半径参数 ρ ∈ R 为无约束参数，激活半径通过 softplus 得到：r = softplus(ρ) + ε，确保正值且数值稳定。
   - 锚点中心和半径初始化为可学习的、跨场景共享的参数。

2. **锚点感知自注意力（Anchor-aware Self-Attention）**：
   - 由锚点中心生成锚点位置编码 p = MLP(PE(μ))；
   - 将位置编码注入 token 特征后再进行自注意力：q̃ = q + p，使 token 间交互依赖其当前三维位置而非仅依赖潜在特征。

3. **锚点-射线交叉注意力（Anchor-to-Ray Cross-Attention）**：
   - 对每个图像 patch 的相机射线（Plücker 形式），计算锚点中心到射线的最近欧氏距离 D(μ, ℓ)；
   - 定义几何偏置 b = −1/2·(D(μ, ℓ) / (σ₀r))²，其中 σ₀ 为固定带宽超参数；
   - 几何偏置加入内容注意力 logits：α = softmax(qᵀk/√d + γb)，γ 为可学习缩放系数；
   - 使查询优先聚合与当前锚点几何位置一致的图像证据。

4. **动态锚点细化（Dynamic Anchor Refinement）**：
   - 每层解码后，由更新后的 token 特征预测锚点中心和半径的残差更新：Δμ = f_μ(q)，Δρ = f_ρ(q)；
   - 锚点状态逐层更新：μ ← μ + Δμ，ρ ← ρ + Δρ。

5. **锚点中心高斯解码（Anchor-Centered Gaussian Decoding）**：
   - 预测每个高斯相对于最终锚点中心的局部偏移 δ，并缩放后得到高斯中心：μ_G = μ_L + r_L · δ；
   - 中心被锚定在局部区域内，而不是自由预测；其余属性（尺度、旋转、颜色、不透明度）由标准 token 预测头生成。

6. **多层渲染监督（Multi-layer Rendering Supervision）**：
   - 对中间解码层和最终层都进行渲染监督，使用图像重建损失 + 可见性正则化，并应用于高斯中心与锚点中心；
   - 各监督层加权求和，权重随层数增大。

### 7. 优点

1. **问题切入点准确**：指出现有查询式 3DGS 中“潜在查询缺乏空间角色”这一关键缺陷，并给出可视化证据，诊断清晰。

3. **几何先验设计合理**：锚点-射线距离偏置直接利用了相机射线几何，从几何上约束证据聚合；半径自适应调节了聚合的感知范围，模型能够适应不同场景稠密/稀疏程度。

### 8. 不足与局限

1. **依赖已知相机位姿**：LocusGS 的锚点-射线几何偏置需要精确的相机参数（通过 Plücker 射线构建），无法直接应用于无位姿（pose-free）场景；论文在局限中也明确承认这一点。
2. **锚点形态简单**：每个锚点仅用一个中心和一个标量（各向同性）半径表示，对细长结构或复杂几何区域的表达能力有限；作者指出更各向异性的锚点或可见性感知的不确定性建模可能会更好。
3. **推理开销增加**：相比 TokenGS，参数量（+8.8%）、存储（+8.8%）和纯前向时间（约 +19%）均有增加，对实时性要求高的应用可能构成负担。
4. **与并发 token 式方法的对比不足**：对 GlobalSplat、C3G、TokenSplat 等同期方法仅作定性讨论，未进行同条件下的定量比较，结论的普遍性仍需更多验证。
5. **训练算力细节缺失**：论文未报告训练所用 GPU 数量、显存占用和训练耗时，不利于复现成本评估。
6. **评估场景有限**：实验集中在 RE10K 和 DL3DV 两类真实场景数据集上，未覆盖室内场景、大规模城市场景或无纹理区域；两视图最小支持时质量仍有限（DL3DV 2 视图 PSNR 仍低于 21）。
